# YATAI G1 実機検証PoC

> 技術評価専用です。Firebase・GitHub・既存本番システムへのアクセスはありません。実売上や個人名を入力しないでください。

## 目的

基本設計書v1.2の第9.1〜9.3節、G1、BD-03 / BD-05をiPhone（Safari）・Android（Chrome）で実機検証するための単一HTMLファイルです。比較用にデスクトップChromiumのテストも実行できます。

## セットアップ（重要：HTTPS必須）

- `index.html`だけを、**旧本番とは無関係な**HTTPSテストサイトで公開してください。新規GitHubリポジトリのGitHub Pages、Firebase Hosting の新規検証プロジェクト等を想定します。
- iPhoneの「ファイル」アプリからHTMLを開くだけでは、Web Locksなどの挙動を正しく検証できません。
- テストページにはログイン、Firebase SDK、APIキーはありません。HTTPS上で同じURLを複数タブで開いてください。
- iOSではSafariとホーム画面追加したPWAを**別の試験ケース**として扱い、ブラウザ内タブとPWA間のロック共有を前提にしないでください。
- AndroidではChromeを使い、端末のOSバージョン・Chromeバージョンを記録してください。

## 検証の進め方

1. 1タブ目で開き「Web Locks 対応」「IndexedDB 対応」「所有中」を確認。
2. 「テスト取引を1件保存」→件数1→再読込→件数1を確認。
3. 「意図的にabortする」→件数が増えないことを確認。
4. 「20件連続保存」→保存件数と監査印件数が一致することを確認。
5. 1タブ目を開いたまま同じURLを2タブ目で開き、2タブ目が「競合：閲覧専用」となり書込できないことを確認。
6. 1タブ目を閉じ、2タブ目で「ロック取得・再試行」→所有中となり、データ件数が保持されることを確認。
7. 画面消灯、他アプリに移動、端末のメモリ逼迫、ブラウザ強制終了後に再開し、保存件数・監査整合・取得状態を確認。
8. 「診断JSON保存」で試験記録を出力。端末名と期待値／実際の結果を`TEST_PLAN.md`に記入。

## 限界

- **Firebaseサーバー送信・二重計上防止APIを試験しません。** これは端末ローカル保存・排他制御PoCです。
- `freeze`発生やOSプロセス破棄は、実機では必ず起こるものではなく、このページだけで強制的に再現することもできません。
- `oncomplete`があっても物理的な消失が絶対に起きないという保証はありません。
- ロック競合の結果は同一オリジン、ブラウザのタブ管理、WebViewの実装などに依存します。
- ダウンロードした診断JSONにはブラウザ情報が含まれるため、公開しないでください。

## データを消すとき

ページの「テスト記録を削除」は`yatai-g1-mobile-poc-v1`というPoC専用IndexedDBだけを削除します。既存の売上、Firebase、ブラウザの他のDBには触れません。
